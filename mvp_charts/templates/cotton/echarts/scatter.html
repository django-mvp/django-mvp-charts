{# @description A scatter chart: the relationship between two numbers, one point per observation. #} {# @strict #} {# @prop name:text | required | description:"Accessible name — what a screen reader announces this chart as" #} {# @prop description:text | required | description:"Text alternative — what the chart shows, for anyone who cannot see it" #} {# @prop :values:text | description:"One series of points, each an [x, y] pair: :values=\"[[1, 4], [2, 9]]\"" #} {# @prop :series:text | description:"Several named series of points: [{'name': …, 'data': [[x, y], …], 'color': …}]" #} {# @prop :config:text | description:"An object carrying any of these same attributes, built in Python. An attribute written on the tag wins over the same key here" #} {# @prop :options:text | description:"Raw ECharts options, deep-merged over everything the component built. Axis names and point size live here" #} {# @prop id:text | description:"Element id. Assigned per request when omitted" #} {% comment %} The one chart type here with no labels attribute: nothing on a scatter chart is named by its position, because both of a point's coordinates are numbers. Telling series apart by colour alone is hardest on this shape — every pair of colours is adjacent when the points overlap — so three series is the comfortable ceiling and a fourth wants a second chart. Every attribute is declared with an empty default on purpose: a component's own default must not beat a config object the author actually wrote, and Cotton cannot tell an absent attribute from one written empty. The defaults live in mvp_charts.echarts.options instead. {% endcomment %} {% load mvp_charts %} {% echarts_chart "scatter" name=name description=description values=values series=series config=config options=options id=id as chart %} {% if chart.name and chart.description %}{{ chart.script }}{% endif %}
