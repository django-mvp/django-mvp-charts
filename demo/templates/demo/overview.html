{% extends "page_view.html" %} {% load mvp %} {% block page.content %} A chart on a Django page is mostly plumbing. You serialise a queryset to JSON, drop a div with an id, then write a script that finds the div and hands the JSON to a charting library — and do all of it again on the next page with a slightly different id. This package moves the plumbing into one Cotton component so the template keeps only the placement. The chart itself is built in the view, with pyecharts. There are no models, no views and no URLs in the package: it renders markup, and that is all. The view builds a chart and puts it in the context: 
from pyecharts.charts import Line

class RevenueView(TemplateView):
    template_name = "revenue.html"

    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context["revenue"] = (
            Line()
            .add_xaxis(["Jan", "Feb", "Mar", "Apr", "May", "Jun"])
            .add_yaxis("Revenue", [820, 932, 901, 934, 1290, 1330])
        )
        return context
The template places it. Its type, its data, its axes, its colours and its tooltip are all set on the chart object in Python, where the whole of ECharts is reachable rather than the part a template attribute happens to name.
Attribute Required What it does
:chart Yes The pyecharts chart to draw. Written with a colon, because it is a Python value.
id Yes The element id. The caption and the text alternative are tied to it, and it is how your own JavaScript finds the figure.
height No A CSS height for the whole figure, caption included. Leave it out and the figure fills the element around it instead.
aspect-ratio No The shape of the figure instead of its height: 2, or 16/9. It takes the width it is given and works the height out. Ignored when height is also set.
name No What a screen reader announces the chart as.
caption No A line printed under the chart, for everybody. Read out with the chart as well.
description No What the chart shows, in words, read instead of the picture. Never shown.
A chart is drawn into a canvas, and a canvas has to be told how big it is. Write a height on the tag, write a ratio and let the width decide the height, or write neither and let the element around it do both. {% comment %} The source is shown rather than captured with show_code, because show_code renders a live preview of whatever it captures — which would put a second chart on the page under each of the ids used below. {% endcomment %} 
<c-chart :chart="revenue" id="sizing-fixed" height="240px" ... />

<c-chart :chart="revenue" id="sizing-ratio" aspect-ratio="16/9" ... />
240 pixels tall, whatever the column does. Narrow the window and it keeps its height while losing width, so the chart grows squatter.
Sixteen by nine, at any width. Narrow the window and the height follows it down, so the chart keeps its shape and the column below it moves up.
A chart is drawn by the browser, so there is a moment before it appears. Every figure spends that moment holding a spinner in its centre, and loses it the instant the chart is on the surface. There is no attribute for this and nothing to switch on. Throttle the network and reload to watch it on any chart here. The charting library is never shipped from here. This project loads it from a public CDN, which suits a demonstration and keeps local development free of a Node toolchain. An application is expected to bundle it instead, importing only the chart types it draws and the renderer they are built with. {% endblock page.content %}
